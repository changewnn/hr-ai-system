# M0 需求决策与规则说明

## 文档信息

| 项目 | 内容 |
|---|---|
| 文档状态 | 已确认，作为 MVP 开发基线 |
| 对应任务 | M0-01 ～ M0-06 |
| 适用范围 | MVP 第一版 |
| 默认业务时区 | `Asia/Shanghai`（UTC+8），通过配置项可调整 |
| 默认数据精度 | 金额 `DECIMAL(12,2)`，天数 `DECIMAL(5,2)` |

## 1. 时间、工作日与考勤规则

### 1.1 时间存储与展示

- 数据库中的时间统一使用 UTC 存储。
- 所有业务日期（打卡日期、请假日期、工资月份）按系统业务时区解释，默认 `Asia/Shanghai`。
- 前端展示和日期筛选使用业务时区，禁止直接按浏览器本地时区改变业务日期。
- 系统配置项：`APP_TIMEZONE`，默认值为 `Asia/Shanghai`。

### 1.2 工作日

- MVP 默认工作日为周一至周五。
- 暂不接入法定节假日和调休日历，周六、周日不计入应出勤日。
- 后续接入节假日配置时，日历服务应优先于固定周一至周五规则。

### 1.3 考勤判定

- 默认上班时间 `09:00`，下班时间 `18:00`。
- 默认迟到和早退阈值均为 5 分钟，超过阈值才计入异常。
- 上班卡早于或等于 `09:05` 不算迟到；晚于 `09:05` 算迟到。
- 下班卡晚于或等于 `17:55` 不算早退；早于 `17:55` 算早退。
- 仅有上班卡或仅有下班卡时，状态为缺卡；缺卡优先于迟到/早退展示，但保留原始打卡时间用于审计。
- 重复打卡取最早上班卡和最晚下班卡，原始打卡事件可选存入扩展表或日志。
- 非工作日不生成应出勤缺卡记录；员工仍不可通过普通打卡接口补造非工作日考勤。

## 2. 请假边界与校验规则

### 2.1 日期和时段

- 请假开始日期不得早于业务时区的当前日期；当天及未来日期允许提交。
- 结束日期不得早于开始日期。
- 单日请假通过开始时段和结束时段表达：上午、下午；单日全天为 1 天，半天为 0.5 天。
- 多日请假按工作日计算，周六、周日不计入时长。
- 跨月请假允许提交，按实际日期拆分到各月份考勤汇总；年假余额按总申请时长扣减。
- MVP 不支持小时级请假。

### 2.2 重叠判断

- 同一员工的请假区间只要存在日期和时段交集，就视为重叠。
- 草稿、待审批、已通过状态均参与重叠校验。
- 已驳回、已撤销状态不参与重叠校验。
- 重叠校验必须在提交和审批通过前再次执行，防止并发提交绕过校验。

### 2.3 年假

- 年假额度按自然年配置和重置，默认按员工配置，没有默认自动额度。
- 剩余年假 = 年度额度 - 已通过年假 - 待审批年假。
- 草稿不占用额度，撤销或驳回后释放额度。
- 提交年假时必须展示提交后的预计余额；余额不足直接拒绝提交。

### 2.4 审批路由

- 员工所属部门存在有效主管时，待审批单路由给该主管。
- 申请人就是部门主管时，自动路由给 ADMIN。
- 部门没有主管时，自动路由给 ADMIN，并记录路由兜底原因。
- 只有当前审批人或 ADMIN 可以执行审批；已处理状态不可重复审批。

## 3. 初始密码与账号策略

- 默认初始密码通过配置项 `DEFAULT_INITIAL_PASSWORD` 提供，生产环境必须显式配置，禁止使用代码内固定生产密码。
- 新建账号设置 `must_change_password=true`。
- 首次登录只允许访问改密接口和必要的当前用户信息接口；改密成功后清除强制改密标记。
- 密码修改必须校验新密码复杂度：至少 8 位，包含字母和数字；不得与最近 3 次密码相同（如实现密码历史表）。
- 账号停用后立即拒绝登录、刷新 Token、打卡和发起业务操作。

## 4. JWT 登出失效方案

- JWT 使用 `jti` 唯一标识，默认有效期 8 小时。
- 登出时将 `revoked:{jti}` 写入 Redis，TTL 设置为 Token 剩余有效期。
- 每次鉴权同时校验签名、过期时间、账号状态和 Redis 黑名单。
- Redis 不可用时，涉及写操作的接口默认拒绝，避免无法判断已注销 Token 是否有效；只读接口按系统可用性策略处理并记录告警。
- 不在 Token 中存放身份证号、工资等敏感信息。

## 5. 简化薪酬和个税规则

### 5.1 薪酬公式

```text
日薪 = 基本工资 / 21.75
出勤扣款 = 缺勤天数 × 日薪 + 迟到早退次数 × 单次扣款
应发工资 = 基本工资 + 岗位津贴
应纳税所得额 = max(0, 应发工资 - 社保个人部分 - 公积金个人部分 - 个税起征点)
实发工资 = 应发工资 - 出勤扣款 - 社保 - 公积金 - 个税
```

- 所有中间结果使用 Decimal，按 2 位小数四舍五入。
- 缺勤天数不包含已通过的请假天数。
- 社保、公积金按薪酬档案固定值计算，MVP 不对接第三方系统。
- 个税起征点默认 5000，可配置但必须记录计算时使用的版本和参数。

### 5.2 默认简化月度税率表

该税率表仅用于 MVP 工资条试算，不代表个税申报结果；税率和速算扣除数必须配置化。

| 月度应纳税所得额 | 税率 | 速算扣除数 |
|---:|---:|---:|
| 不超过 3,000 | 3% | 0 |
| 3,000～12,000 | 10% | 210 |
| 12,000～25,000 | 20% | 1,410 |
| 25,000～35,000 | 25% | 2,660 |
| 35,000～55,000 | 30% | 4,410 |
| 55,000～80,000 | 35% | 7,160 |
| 超过 80,000 | 45% | 15,160 |

```text
个税 = max(0, 应纳税所得额 × 税率 - 速算扣除数)
```

## 6. MVP 支撑实体补充

需求文档列出的核心业务表实际为 11 张；为支撑消息、审计、Token 失效和 Agent，MVP 额外增加以下实体：

| 实体 | 用途 | 最小字段建议 |
|---|---|---|
| `message` | 站内通知 | id、recipient_user_id、type、title、content、related_id、read_at、created_at |
| `audit_log` | 关键操作留痕 | id、actor_user_id、action、resource_type、resource_id、before_json、after_json、ip、created_at |
| `token_revocation` | JWT 登出失效 | jti、user_id、expires_at、revoked_at；主存 Redis，可选持久化 |
| `salary_adjustment` | 发布后补发/修正 | id、salary_record_id、amount、reason、status、approved_by、created_at |
| `agent_conversation` | Agent 会话 | id、user_id、title、created_at、updated_at |
| `agent_message` | Agent 对话消息 | id、conversation_id、role、content、tool_name、tool_args、confirmation_status、created_at |
| `policy_document` | 制度文档及版本 | id、name、version、source_uri、status、checksum、created_at |
| `policy_chunk` | RAG 文档分片 | id、document_id、content、embedding_ref、section、metadata_json |

## 7. 明确的非目标

- 不实现法定节假日自动同步，节假日影响需后续通过日历配置扩展。
- 不实现工资批量导入、银行代发、社保公积金接口和正式个税申报。
- 不实现多级审批、代理审批和审批转交。
- 不允许 Agent 修改员工档案、薪酬档案、审批结果或替代主管审批。
