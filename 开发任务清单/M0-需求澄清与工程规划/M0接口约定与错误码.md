# M0 接口约定与错误码

## 1. REST 接口约定

### 1.1 基础路径与请求头

- 基础路径：`/api`。
- JSON 请求和响应使用 `application/json; charset=utf-8`。
- 鉴权请求头：`Authorization: Bearer <JWT>`。
- 日期格式：`YYYY-MM-DD`；时间格式：ISO 8601 UTC，例如 `2026-10-08T01:30:00Z`。
- 月份格式：`YYYY-MM`。
- 金额以字符串返回，避免前端浮点精度丢失，例如 `"8000.00"`。

### 1.2 统一响应结构

成功：

```json
{
  "code": 0,
  "error_key": "OK",
  "message": "操作成功",
  "data": {},
  "request_id": "req_01..."
}
```

失败：

```json
{
  "code": 40001,
  "error_key": "LEAVE_OVERLAP",
  "message": "请假时间与已有申请重叠",
  "data": null,
  "request_id": "req_01..."
}
```

列表接口统一返回：

```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0
}
```

### 1.3 HTTP 状态码

| HTTP 状态码 | 使用场景 |
|---:|---|
| 200 | 查询、更新、审批、试算成功 |
| 201 | 创建资源成功 |
| 204 | 删除或登出成功且无响应体 |
| 400 | 请求格式、字段或业务参数无效 |
| 401 | 未登录、Token 无效或已失效 |
| 403 | 已登录但没有资源权限 |
| 404 | 资源不存在或对当前用户不可见 |
| 409 | 状态冲突、重复资源、并发冲突 |
| 422 | Schema 校验失败 |
| 429 | 登录或接口限流 |
| 500 | 未预期服务错误 |

## 2. 分页、筛选和幂等

- 分页参数：`page` 从 1 开始，`page_size` 默认 20，最大 100。
- 排序参数使用白名单字段，禁止将原始字段直接拼接 SQL。
- 创建请假、打卡、发布工资条等写操作支持 `Idempotency-Key`；重复请求返回第一次结果。
- 重要写接口在响应中返回 `request_id`，日志和审计记录使用同一标识串联。

## 3. 核心错误码

业务错误码使用独立的五位数范围，不直接复用 HTTP 400/401/403/409 等状态码。HTTP 状态码只表示协议层结果，响应体中的 `code` 表示业务结果，`error_key` 用于程序可读的稳定标识。

| 业务码范围 | 领域 |
|---:|---|
| `10000`～`10999` | 认证、账号与权限 |
| `20000`～`20999` | 组织、岗位与员工 |
| `30000`～`30999` | 考勤 |
| `40000`～`40999` | 请假与审批 |
| `50000`～`50999` | 薪酬与工资条 |
| `60000`～`60999` | Agent 与政策问答 |
| `90000`～`90999` | 通用系统错误 |

| 业务码 | `error_key` | HTTP | 含义 |
|---:|---|---:|---|
| 0 | `OK` | 200 | 成功 |
| 10001 | `AUTH_INVALID_CREDENTIALS` | 401 | 账号或密码错误 |
| 10002 | `AUTH_TOKEN_INVALID` | 401 | Token 无效、过期或已登出 |
| 10003 | `AUTH_ACCOUNT_DISABLED` | 403 | 账号已停用 |
| 10004 | `AUTH_PASSWORD_CHANGE_REQUIRED` | 403 | 必须先修改初始密码 |
| 10005 | `AUTH_LOGIN_LOCKED` | 429 | 登录失败次数超限 |
| 10006 | `PERMISSION_DENIED` | 403 | 无操作权限 |
| 10007 | `RESOURCE_NOT_FOUND` | 404 | 资源不存在或不可见 |
| 20001 | `DEPARTMENT_HAS_CHILDREN` | 409 | 部门存在下级部门，不能删除 |
| 20002 | `DEPARTMENT_HAS_EMPLOYEES` | 409 | 部门存在员工，不能删除 |
| 20003 | `POSITION_IN_USE` | 409 | 岗位仍被员工引用 |
| 20004 | `EMPLOYEE_NO_IMMUTABLE` | 409 | 工号创建后不可修改 |
| 20005 | `EMPLOYEE_ALREADY_RESIGNED` | 409 | 员工已离职 |
| 30001 | `ATTENDANCE_NOT_ALLOWED` | 400 | 当前状态不允许打卡 |
| 30002 | `ATTENDANCE_ALREADY_FINALIZED` | 409 | 考勤已被 HR 调整，不能自动覆盖 |
| 40001 | `LEAVE_DATE_IN_PAST` | 400 | 请假日期早于当前业务日期 |
| 40002 | `LEAVE_INVALID_RANGE` | 400 | 请假日期或时段无效 |
| 40003 | `LEAVE_OVERLAP` | 409 | 请假时间与已有申请重叠 |
| 40004 | `LEAVE_BALANCE_INSUFFICIENT` | 409 | 年假余额不足 |
| 40005 | `LEAVE_APPROVER_NOT_FOUND` | 409 | 未找到有效审批人 |
| 40006 | `LEAVE_INVALID_TRANSITION` | 409 | 请假状态不允许当前操作 |
| 40007 | `LEAVE_APPROVAL_FORBIDDEN` | 403 | 当前用户不是审批人且不是 ADMIN |
| 50001 | `SALARY_CONFIG_NOT_FOUND` | 409 | 员工缺少有效薪酬档案 |
| 50002 | `SALARY_CALCULATION_INVALID` | 400 | 薪酬计算参数或数据无效 |
| 50003 | `SALARY_ALREADY_PUBLISHED` | 409 | 工资条已发布，不能直接修改 |
| 60001 | `AGENT_CONFIRMATION_REQUIRED` | 409 | 变更操作需要二次确认 |
| 60002 | `AGENT_SCOPE_FORBIDDEN` | 403 | Agent 请求超出当前员工权限 |
| 60003 | `POLICY_NO_EVIDENCE` | 404 | 知识库没有找到可引用依据 |
| 90001 | `RATE_LIMITED` | 429 | 请求频率超过限制 |
| 90099 | `INTERNAL_ERROR` | 500 | 未预期服务错误 |

## 4. 权限判定顺序

后端所有业务接口按以下顺序执行：

1. 解析并验证 JWT。
2. 校验账号启用状态、Token 是否已撤销、是否需要强制改密。
3. 校验角色权限。
4. 根据角色注入数据范围：本人、本部门或全量。
5. 查询资源并执行业务状态和字段校验。
6. 执行事务、写审计日志和发送消息。

不得通过前端传入的 `employee_id`、`department_id` 或角色字段扩大数据范围。

## 6. 版本和变更规则

- 初版接口前缀固定为 `/api`；发生不兼容变更时升级为 `/api/v2`。
- 新增业务错误码必须从对应领域的独立范围段分配，禁止使用 HTTP 状态码作为 `code`。
- HTTP 状态码和业务错误码必须同步返回：例如请假重叠返回 HTTP `409`、业务码 `40003`、`error_key=LEAVE_OVERLAP`。
- 新增错误码必须同步更新本文件和 OpenAPI 文档。
- 任何改变状态机、金额公式、权限范围或数据含义的变更，必须先更新 M0 决策文档，再修改代码和测试。
