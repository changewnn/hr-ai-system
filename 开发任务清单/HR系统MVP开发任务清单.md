# 最小化 HR 系统（MVP）开发任务清单

## 1. 项目目标与交付范围

交付一个支持 50～100 人单机部署的小型 HR 系统，完成以下业务闭环：

> 入职建档 → 创建账号 → 员工打卡 → 请假申请 → 主管审批 → 考勤汇总 → 月度薪酬试算 → 工资条发布 → 员工查看

本期角色：`ADMIN`（HR 管理员）、`MANAGER`（部门主管）、`EMPLOYEE`（员工）。

本期不做：招聘、绩效、培训、排班、GPS/人脸识别、社保/银行/个税第三方对接、多级审批、独立移动 App。

## 2. 开发原则

- 所有后端接口统一执行 JWT 鉴权、RBAC 校验和数据范围校验。
- 员工只能访问自己的档案、考勤、请假和工资条；主管只能访问本部门范围。
- 关键写操作必须记录审计日志，敏感数据加密存储并脱敏展示。
- 请假审批、考勤联动、消息通知使用数据库事务保证一致性。
- 金额使用 Decimal，时间统一 UTC 存储，展示时转换为系统本地时区。
- 已发布工资条不可修改，修正通过补发记录实现。

## 5. 推荐实施顺序

1. 完成 M0～M3，先打通数据库、鉴权和权限边界。
2. 完成 M4，形成“部门—岗位—员工—账号”的入职基础链路。
3. 完成 M5～M6，打通“打卡—请假—审批—考勤联动”。
4. 完成 M7，打通月度薪酬和工资条发布。
5. 完成 M8～M9，补齐管理端和员工端操作界面。
6. 完成 M10，接入站内消息、Agent 和政策知识库。
7. 完成 M11，进行联调、性能、安全、备份和上线验收。

## 6. 每个阶段的完成定义

- 数据库迁移可重复执行，初始化数据可在空库启动。
- 后端接口具备参数校验、权限校验、错误处理和自动化测试。
- 前端页面具备加载中、空数据、错误、成功反馈和权限隐藏状态。
- 关键写操作具备事务和审计记录。
- 阶段完成前必须更新接口文档、数据库变更说明和测试结果。

## 7. MVP 验收清单

- [ ] ADMIN 可以创建部门、岗位、员工和账号。
- [ ] EMPLOYEE 首次登录必须修改密码，离职后不能登录和打卡。
- [ ] EMPLOYEE 可以上下班打卡并查看个人月度考勤。
- [ ] EMPLOYEE 可以提交请假，MANAGER/ADMIN 可以按权限审批。
- [ ] 审批通过后考勤和月度汇总正确标记为请假。
- [ ] ADMIN 可以按月试算并发布工资条。
- [ ] EMPLOYEE 只能查看自己的工资条和档案。
- [ ] 审批和工资条发布产生站内消息及未读数。
- [ ] Agent 不得越权、代审批或修改薪资，变更动作必须二次确认。
- [ ] 核心流程、权限隔离、敏感数据保护和备份恢复验证通过。
