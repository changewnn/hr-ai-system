# 最小化 HR 系统（MVP）开发任务清单

## 1. 项目目标与交付范围

交付一个支持 50～100 人单机部署的小型 HR 系统，完成以下业务闭环：

> 入职建档 → 创建账号 → 员工打卡 → 请假申请 → 主管审批 → 考勤汇总 → 月度薪酬试算 → 工资条发布 → 员工查看

本期角色：`ADMIN`（HR 管理员）、`MANAGER`（部门主管）、`EMPLOYEE`（员工）。

本期不做：招聘、绩效、培训、排班、GPS/人脸识别、社保/银行/个税第三方对接、多级审批、独立移动 App。

## 2. 开发原则

- 所有后端接口统一执行 JWT 鉴权、RBAC 校验和数据范围校验。
- 员工只能访问自己的档案、考勤、请假和工资条；主管只能访问本部门范围。
- 关键写操作必须记录审计日志，敏感数据加密存储并脱敏展示。
- 请假审批、考勤联动、消息通知使用数据库事务保证一致性。
- 金额使用 Decimal，时间统一 UTC 存储，展示时转换为系统本地时区。
- 已发布工资条不可修改，修正通过补发记录实现。

## M10：消息、Agent 与政策问答（重规划后正式版本）

> 本节于 2026-10-10 根据评审结果重新规划，是 M10-01 至 M10-12 的正式开发顺序和验收依据。实施路径固定为“政策知识库 -> Agent RAG 问答 -> 业务工具调用 -> 安全与交付”。如与文件中早期 M10 描述存在歧义，以本节及《M10-IT实施方案》为准。

### 已确认技术决策

1. LLM 使用 DeepSeek，向量模型使用千问，分别通过 Provider 适配层接入；API Key 仅保存在服务端环境变量或部署 Secret 中。
2. 向量存储使用现有 PostgreSQL + pgvector，不引入独立向量数据库；向量列维度必须与选定的千问向量模型一致。
3. Agent 变更类工具只开放“提交本人请假”，不开放修改、撤销、审批、薪资修改或代他人操作。
4. 政策问答无可靠依据时，自动给 HR 发送站内咨询消息，并向员工显示“未找到可靠政策依据，已转交 HR”。
5. 政策文档支持带文本层的 PDF 以及 DOCX、MD、TXT，暂不支持扫描 PDF OCR。
6. Agent 回答使用 SSE 实时响应，同时提供连接中断、超时和失败后的明确错误状态及重试能力。
7. Agent 会话、Agent 消息和 Agent 审计数据保留 180 天，到期由定时任务清理，并记录清理审计。
8. ADMIN 使用员工 Agent 时也只能访问本人数据；管理员对其他员工的管理查询继续使用管理端现有功能。
9. Agent 编排框架使用 LangGraph。采用显式 `StateGraph`、受控节点和条件边，不使用可自由选择任意工具的开放式 ReAct Agent；业务权限和数据范围仍由现有 FastAPI Service 层最终校验。

### 第一阶段：政策知识库

#### M10-01：知识库基础设施与数据模型

**目标**：为政策文档发布、向量存储和任务处理建立基础。

**开发内容**：

- 确认 PostgreSQL、pgvector 版本和千问向量维度。
- 建立政策文档、文档版本、文档分块、索引任务等数据表。
- 配置千问 Embedding Provider，并建立政策原文件存储目录。
- 定义 `UPLOADED -> PARSING -> INDEXING -> READY -> PUBLISHED -> ARCHIVED/FAILED` 状态流转。
- 增加知识库 `60100-60199` 业务错误码。
- 增加索引任务重试次数、失败原因、任务锁及幂等字段。

**验收标准**：

- Alembic 迁移可以正常升级和回滚。
- pgvector 向量字段及索引可以正常创建。
- 千问向量接口连通性验证通过。
- 文档、版本和索引任务状态可以持久化并正确流转。

#### M10-02：政策文档上传、版本与发布接口

**目标**：完成管理端知识库的后端管理能力。

**开发内容**：

- 实现创建政策文档、上传首个版本及上传后续版本。
- 实现文档列表、详情、版本历史、任务状态和失败原因查询。
- 实现 READY 版本发布、失败任务重试和版本归档。
- 校验文件类型、大小、MIME、文件头和文件哈希。
- 支持带文本层的 PDF 以及 DOCX、MD、TXT；扫描 PDF 暂不做 OCR。
- 同一政策只允许一个当前发布版本；发布新版本时在同一事务中归档旧版本。
- 所有知识库管理接口仅允许 ADMIN 访问。

**验收标准**：

- 非管理员不能访问知识库管理接口。
- 重复文件可以被识别，重复请求不会创建重复版本。
- 未完成索引的版本不能发布。
- 发布新版本时旧版本自动归档。
- 扫描 PDF 返回明确的不支持提示。

#### M10-03：文档解析、切分、向量化与存库

**目标**：打通从原文件到 pgvector 的完整索引链路。

**开发内容**：

- 按文件类型提取文本，保留标题、章节、页码或段落位置。
- 清理页眉、页脚、重复空白等无效内容，但不改写政策原意。
- 按章节优先切分，token 窗口兜底；建议分块 500-800 tokens、重叠 80-120 tokens。
- 批量调用千问向量模型，将文本、metadata 和 embedding 写入 pgvector。
- 通过后台任务执行解析与索引，支持失败重试、任务锁和幂等处理。
- 文件版本变化时重建对应索引，不影响已发布旧版本继续提供服务。

**验收标准**：

- 上传文档能够按状态流转并最终进入 READY。
- 每个分块可以追溯到文档、版本、章节和页码/段落。
- 重复执行索引任务不会产生重复分块。
- 向量服务失败后可以重新执行。
- 单个文档失败不会阻断其他文档处理。

#### M10-04：管理端政策文档页面

**目标**：让管理员可以通过页面完成政策管理和发布。

**开发内容**：

- 实现政策文档列表、创建文档、上传新版本和版本历史页面。
- 展示解析、向量化、READY、发布、归档和失败状态。
- 展示失败原因并支持重新处理。
- 实现发布和归档操作，发布操作必须二次确认。
- 增加管理员检索测试功能，用于发布前验证召回片段和来源。

**验收标准**：

- 管理员可以从页面完成上传、索引验证和发布。
- 页面状态与后端任务状态保持一致，刷新后状态不丢失。
- 发布后可以通过检索测试找到正确片段。
- 非管理员无法通过页面或直接请求执行管理操作。

### 第二阶段：Agent RAG 问答

#### M10-05：政策检索服务与引用能力

**目标**：形成独立、可测试的政策 RAG 检索服务。

**开发内容**：

- 实现 pgvector 相似度检索和 PostgreSQL 关键词/全文检索。
- 对向量和关键词结果进行混合召回、去重和排序。
- 只检索 PUBLISHED 且在生效期内的版本。
- 设置最低相关度阈值，默认召回 8 个片段，重排后提供最多 4 个上下文片段。
- 返回文档名、版本、章节、页码/段落、原文片段和 chunk ID 等结构化引用。
- 建立政策检索测试集和预期召回结果。

**验收标准**：

- 未发布、已归档、未生效和已过期版本不会被检索。
- 测试问题能够召回预期政策片段。
- 引用可以准确追溯到原文。
- 无可靠结果时返回“无依据”，不得生成猜测结论。

#### M10-06：LangGraph 会话、状态图与 SSE

**目标**：建立 Agent 运行框架，暂不开放员工业务工具。

**开发内容**：

- 创建 Agent 会话和消息历史，并绑定 JWT 用户及员工身份。
- 使用 LangGraph `StateGraph` 建立显式节点和条件边，不使用开放式 ReAct Agent。
- 使用 PostgreSQL checkpointer 保存流程状态，校验 `thread_id` 与用户、会话归属。
- 接入 DeepSeek LLM Provider。
- 使用 SSE 输出 `message_delta`、`citation`、`tool_status`、`confirmation_required`、`completed`、`error` 和心跳事件。
- 支持断线后的会话恢复，配置模型超时、工具次数和图递归上限。

**验收标准**：

- 用户只能访问自己的会话、消息和 checkpoint。
- SSE 可以持续输出并以 completed 或 error 明确结束。
- 连接中断和重复请求不会产生重复消息。
- checkpoint 不能跨用户或跨会话恢复。
- 模型超时有明确错误状态，且不会泄露内部 Prompt 或完整图状态。

#### M10-07：Agent 政策 RAG 问答

**目标**：将政策检索接入 LangGraph，形成可用的政策助手。

**开发内容**：

- 建立“输入安全检查 -> 问题分类 -> 政策检索 -> 证据判断 -> 回答生成 -> 引用组装 -> 审计”的状态图。
- 将政策检索作为 LangGraph 受控节点。
- DeepSeek 只能依据召回片段生成政策回答。
- 前端通过 SSE 展示实时回答和可展开的结构化引用。
- 防止政策文档 Prompt 注入，限制上下文长度和召回片段数量。
- 简单结果允许使用固定模板生成，降低模型调用成本和延迟。

**验收标准**：

- 所有政策结论均带有真实引用，引用与结论一致。
- 模型不能编造不存在的文档、版本、章节或页码。
- 政策文档中的恶意指令不能改变系统权限或调用路径。
- 无证据时不输出确定性政策结论。

#### M10-08：无依据转 HR 咨询与站内消息

**目标**：为政策问答无法回答的场景形成业务闭环。

**开发内容**：

- 无召回、相关度不足、政策冲突或模型失败时创建 HR 咨询消息。
- 咨询消息包含员工、问题摘要、会话标识、创建时间和会话跳转信息。
- 使用幂等键避免相同会话和问题重复发送。
- 支持 HR 查看咨询详情并回复员工，员工通过站内消息接收回复。
- 员工端显示“未找到可靠政策依据，已转交 HR”。
- 补齐相关消息的未读数、详情、单条已读和全部已读能力。

**验收标准**：

- 相同会话和问题不会反复创建咨询消息。
- 咨询消息只发送给配置的 HR 收件人。
- HR 回复能够准确送达原提问员工。
- 消息中不包含模型密钥、JWT 或其他敏感凭证。

### 第三阶段：业务工具调用

#### M10-09：本人数据只读工具

**目标**：在 RAG 稳定后逐步开放低风险业务查询。

**开发内容**：

- 建立服务端工具注册表和独立 Pydantic 参数模型。
- 开放本人考勤、本人年假余额、本人请假记录、本人已发布工资条和本人档案工具。
- LangGraph 只通过明确条件边进入固定工具节点。
- 工具节点调用现有 Service 层，不直接执行 SQL 或访问任意外部 HTTP 地址。
- `employee_id`、`user_id` 和角色只允许由服务端根据 JWT 注入。
- 工具返回统一结构化结果；工资条等敏感数据优先使用后端固定模板展示。
- 限制单轮工具调用次数。

**验收标准**：

- 用户不能通过 Prompt、请求参数或会话状态查询其他员工。
- ADMIN 使用员工 Agent 时也只能查询本人数据。
- 工具失败不会被模型描述为成功。
- 未注册工具无法被调用，工具参数中的额外字段会被拒绝。

#### M10-10：本人请假提交与二次确认

**目标**：开放唯一的 Agent 写操作。

**开发内容**：

- 解析请假参数，缺少参数时通过多轮对话补齐。
- 调用现有 Service 校验并生成标准化请假预览。
- 通过 LangGraph `interrupt` 暂停流程，等待用户确认或取消。
- 确认令牌绑定用户、会话、checkpoint、工具和规范化参数哈希，短期有效且只能使用一次。
- 确认后通过 `Command(resume=...)` 恢复，并在落库前重新执行业务校验。
- 使用数据库事务和幂等键，避免重复确认产生重复请假记录。
- 拒绝修改、撤销、审批、代他人请假和修改薪资。

**验收标准**：

- 用户确认前数据库没有新增请假记录。
- 参数变化后必须重新生成预览和确认令牌。
- 重复点击或并发确认最多生成一条请假记录。
- 其他用户或其他会话不能使用该确认令牌。
- 取消、过期或 checkpoint 恢复失败时不能落库。

### 第四阶段：安全、稳定性与交付

#### M10-11：权限、审计与数据保留

**目标**：建立完整的数据范围控制和可追踪能力。

**开发内容**：

- 记录模型处理结果、工具调用、越权拒绝、确认、取消和执行结果。
- 记录政策上传、发布、归档、索引失败和 HR 转接事件。
- 对 Prompt、工具参数和审计内容中的敏感字段脱敏。
- Agent 会话、消息、checkpoint 和 Agent 审计数据保留 180 天。
- 定时分批清理过期数据，并为清理任务写审计日志。
- 对用户、SSE 连接、模型调用和敏感接口实施限流。

**验收标准**：

- 每次 Agent 操作可以通过 `request_id`、`conversation_id` 和 `tool_call_id` 追踪。
- 日志不包含密码、JWT、API Key、完整身份证号或完整工资明细。
- 180 天清理任务不会删除请假、工资等正式业务记录。
- 越权行为和清理结果具有明确审计记录。

#### M10-12：异常降级、自动化测试与部署文档

**目标**：完成生产级兜底、回归测试和可复现部署。

**开发内容**：

- 处理 DeepSeek 超时、限流和非法输出。
- 处理千问向量接口失败、索引任务失败和重试。
- 处理 LangGraph 节点异常、checkpoint 恢复失败和递归超限。
- 处理 SSE 断线、反向代理缓冲/超时、Redis 不可用和 HR 消息发送失败。
- 编写单元测试、API 集成测试、权限测试、并发/幂等测试和 Playwright E2E。
- 补充数据库迁移、pgvector 检查、初始化、模型配置、索引重建、启动、健康检查和回滚命令。
- 使用 `AGENT_ENABLED` 功能开关逐步启用 Agent。

**验收标准**：

- 任意异常都不会导致越权、重复执行或未确认写入。
- 模型或工具失败不会展示虚假成功。
- 自动化测试覆盖知识库、RAG、SSE、HR 转接、只读工具和请假二次确认。
- 新环境可以仅按部署文档完成初始化和启动。

### M10 推荐实施顺序

```text
政策知识库：M10-01 -> M10-02 -> M10-03 -> M10-04
Agent RAG： M10-05 -> M10-06 -> M10-07 -> M10-08
业务工具：  M10-09 -> M10-10
安全交付：  M10-11 -> M10-12
```

每个阶段均应独立验收：第一阶段交付可发布和向量化的政策知识库；第二阶段交付带引用和 HR 转接的政策问答；第三阶段再开放本人业务查询和唯一写操作；第四阶段完成安全加固、自动化测试与部署交付。

### M10 实施前配置项

- 明确政策咨询消息的 HR 收件人分配规则：固定 HR、HR 角色全体或按员工所属部门匹配。该规则确定后，需同步写入 M10-02、M10-11 的测试用例和部署配置。
- 配置 DeepSeek 和千问的 Base URL、API Key、具体模型名称；确认千问向量维度。
- 固定并验证兼容当前 Python/FastAPI/Pydantic/SQLAlchemy 版本的 LangGraph 依赖版本；为图节点、条件边、checkpoint 和 interrupt/resume 准备自动化测试。
- 核验当前 PostgreSQL 和 pgvector 扩展版本，并验证目标向量维度对应的索引可正常创建。
- 准备至少 3 份不含生产敏感数据的政策测试文档及预期问答样例。
