# M10 第四阶段：安全、稳定性与交付实现说明

## 已完成

- Agent 普通请求和 SSE 请求使用 Redis 计数限流；Redis 不可用时敏感 Agent 请求安全失败，不绕过限制。
- Agent 工具、确认生成、请假确认、RAG 回答和 HR 转人工写入 `audit_log`，通过 `request_id`、会话和业务资源关联。
- 审计字段递归脱敏：密码、JWT、访问令牌、API Key、Secret、确认令牌不会写入审计 JSON；过长文本截断。
- 新增 `cleanup_agent_data.py`，按 180 天保留策略每次最多清理 500 个 Agent 会话、消息和确认状态，不删除正式请假、考勤或工资记录。
- 全局未知异常和 5xx 业务异常统一返回安全错误消息，详细堆栈只记录服务端日志。
- 增加 Agent 工具识别、请假参数解析、审计脱敏和日期 JSON 序列化测试。

## 部署

```powershell
docker compose build backend frontend
docker compose up -d backend frontend nginx
docker compose exec backend alembic -c alembic.ini upgrade head
docker compose exec backend python -m compileall -q app scripts
docker compose exec backend python scripts/cleanup_agent_data.py
```

配置项：

```env
HR_AGENT_ENABLED=false
HR_AGENT_RATE_LIMIT_PER_MINUTE=30
HR_AGENT_SSE_RATE_LIMIT_PER_MINUTE=10
HR_AGENT_RETENTION_DAYS=180
```

建议生产环境通过 Windows 任务计划程序每日执行清理脚本，完成测试和灰度后再将 `HR_AGENT_ENABLED` 改为 `true`。
