# 最小化HR系统（MVP）需求文档

# 项目概述

**一句话定位：**面向小团队的一套轻量人事管理系统，一期覆盖员工信息、组织管理、考勤打卡、请假审批、简单薪酬计算五大模块，同时提供 HR 管理端与员工自助端，替代 Excel 表格管理，形成「入职建档 → 打卡 → 请假审批 → 月度发薪 → 工资条」的完整业务闭环。

## 建设目标

- 以最小可用成本支撑 50—100 人规模公司的基础人事管理，单机部署即可运行。

- 员工自助办理考勤与请假，减少 HR 重复沟通；主管在线审批，流程留痕。

- 薪酬按月自动汇总考勤计算，一键生成工资条，员工可自助查看。

## 范围边界

|维度|内容|
|---|---|
|**本期包含**|账号与权限、部门与岗位、员工档案、上下班打卡与考勤汇总、请假申请与单级审批、月度薪酬试算与工资条、站内消息通知、员工自助端|
|**本期不包含**|- 招聘、绩效、培训、排班管理<br>- 社保公积金第三方系统对接、银行代发、个税申报对接<br>- 定位/GPS 打卡校验、人脸识别打卡<br>- 多级审批流、薪资批量导入、多语言、独立移动 App（以 H5 为主）|

## 系统整体架构

系统分为展示端、应用层与数据层三层，三类用户分别通过 HR 管理端与员工自助端使用。

# 用户角色与权限

系统采用 RBAC 权限模型，共三类角色。审批与数据范围均按角色控制，后端接口必须校验越权访问。

|角色|职责|核心权限|
|---|---|---|
|**HR管理员**（ADMIN）|系统配置与全量人事管理|- 部门、岗位、员工档案增删改查与导出<br>- 考勤规则配置、月度考勤汇总查看<br>- 薪酬档案维护、月度薪酬计算与发布<br>- 账号创建、审批兜底|
|**部门主管**（MANAGER）|本部门管理|- 审批本部门员工的请假申请<br>- 查看本部门员工档案与考勤|
|**员工**（EMPLOYEE）|自助使用|- 上下班打卡、查看个人考勤<br>- 发起请假、撤销待审批申请<br>- 查看个人工资条与档案（只读）|

# 功能需求

## 登录与账号

- **HR\-F\-01** 登录方式：工号/手机号 \+ 密码，后端签发 JWT，有效期 8 小时，登出即失效。

- **HR\-F\-02** 账号由 HR 管理员创建，一人一号，绑定员工档案；密码使用 BCrypt 加密存储。

- **HR\-F\-03** 新员工账号默认初始密码，首次登录后强制修改（MVP 内实现，作为可配置项）。

- **HR\-F\-04** 离职员工的账号自动停用，无法登录与打卡。

## 组织管理

- **HR\-F\-05** 部门按树形结构维护（上下级部门），支持新增、编辑、删除、查询；删除时若存在下级部门或员工则拒绝（逻辑删除）。

- **HR\-F\-06** 岗位为独立字典，支持新增、编辑、删除、查询；被员工引用时不可物理删除。

- **HR\-F\-07** 每个部门可指定一名部门主管（MANAGER），用于请假审批路由。

## 员工信息管理

- **HR\-F\-08** 员工档案字段：工号、姓名、性别、手机号、邮箱、身份证号、部门、岗位、入职日期、员工状态（在职/离职）、紧急联系人及电话。

- **HR\-F\-09** 工号系统自动生成（如 E \+ 年月日 \+ 3 位序号），创建后不可修改。

- **HR\-F\-10** 列表支持按部门、状态、关键词（姓名/工号/手机号）筛选，分页展示，支持导出 Excel。

- **HR\-F\-11** 离职操作：员工状态置为离职、账号停用，历史考勤、请假、薪酬数据保留，不可删除。

- **HR\-F\-12** 身份证号等敏感字段 AES 加密存储，列表页脱敏展示（如 110\*\*\*\*\*\*\*\*\*\*\*1234），仅详情页按权限可见。

- **HR\-F\-13** 员工档案编辑记录操作日志（谁在何时改了什么）。

## 考勤管理

- **HR\-F\-14** 考勤规则可配置：标准上下班时间（默认 09:00—18:00）、迟到/早退阈值（默认超过 5 分钟计迟到/早退）、工作日（周一至周五）。

- **HR\-F\-15** 打卡：员工每日可打上班卡与下班卡，一天生成一条考勤记录；重复打卡取最早上班卡、最晚下班卡。

- **HR\-F\-16** 考勤状态自动判定：正常、迟到、早退、缺卡（漏打任一卡）、请假（与通过审批的请假单联动）。

- **HR\-F\-17** 月度考勤汇总：按员工输出出勤天数、迟到/早退次数、请假天数、缺勤天数，作为薪酬计算依据。

- **HR\-F\-18** 考勤记录只读，异常修正走「HR 手工调整」操作并留日志，员工不可自行修改。

## 请假管理

- **HR\-F\-19** 请假类型：年假、事假、病假、调休，类型字典可配置；年假设年度额度，事假/病假/调休不限额。

- **HR\-F\-20** 年假额度由 HR 按员工配置，按自然年重置；员工提交时可实时看到剩余额度。

- **HR\-F\-21** 请假申请字段：类型、开始日期、结束日期、上/下午粒度、时长（自动计算，半天=0\.5 天）、事由。

- **HR\-F\-22** 提交校验：年假余额不足、与已有申请时间重叠、日期早于当前日期时拒绝提交。

- **HR\-F\-23** 审批流：单级审批，路由到员工所属部门主管；若审批人即申请人本人，自动转 HR 管理员审批。

- **HR\-F\-24** 状态机：草稿 → 待审批 → 已通过 / 已驳回；待审批状态下申请人可撤销（已撤销）。

- **HR\-F\-25** 审批通过后自动联动考勤：对应日期考勤状态标记为请假，并在月度汇总中计入请假天数。

- **HR\-F\-26** 审批记录完整留痕：审批人、动作（通过/驳回）、意见、时间。

## 薪酬计算（简单版）

- **HR\-F\-27** 薪酬档案：基本工资、岗位津贴、社保个人部分、公积金个人部分（MVP 为固定配置值）、个税起征点（默认 5000）。

- **HR\-F\-28** 计算规则：日薪 = 基本工资 ÷ 21\.75；出勤扣款 = 缺勤天数 × 日薪 \+ 迟到/早退次数 × 单次扣款（默认 20 元，可配置）；个税按简化速算扣除数计算。

- **HR\-F\-29** 实发工资 = 基本工资 \+ 岗位津贴 − 出勤扣款 − 社保 − 公积金 − 个税。

- **HR\-F\-30** 计算流程：HR 选择月份 → 系统汇总当月考勤 → 试算生成草稿工资条 → HR 核对后确认发布 → 员工端可见。

- **HR\-F\-31** 工资条字段：月份、基本工资、津贴、出勤扣款、社保、公积金、个税、应发、实发；发布后不可修改，修正走补发记录。

- **HR\-F\-32** 员工仅能查看本人的工资条，HR 可查看全员。

## 员工自助端

- **HR\-F\-33** 工作台：展示今日打卡状态、本月出勤摘要（出勤/迟到/请假天数）、未读消息数。

- **HR\-F\-34** 打卡：上班/下班打卡按钮，展示当日打卡时间与判定结果。

- **HR\-F\-35** 请假：发起申请（含额度提示）、我的申请列表（状态与审批记录）、撤销操作。

- **HR\-F\-36** 工资条：按月查看历史工资条明细。

- **HR\-F\-37** 个人档案：只读查看本人信息，不可编辑。

## 消息通知

- **HR\-F\-38** 站内消息三类：审批待办提醒（主管）、审批结果通知（员工）、工资条发布通知（员工）。

- **HR\-F\-39** 消息含已读/未读状态与未读数角标；邮件/企业微信推送列为后续扩展，MVP 不做。

## 员工自助 Agent 与政策问答

在员工自助端叠加对话式智能助手，员工以自然语言完成高频人事事务与制度查询；Agent 通过工具调用复用现有业务 API，不改变系统权限模型。

- **HR\-F\-40** 员工自助 Agent 入口：员工自助端内置对话式智能助手，支持自然语言输入，识别意图后执行对应操作或返回结果。

- **HR\-F\-41** 支持场景：查询个人考勤记录与月度汇总、查询年假剩余额度、发起请假申请（自动解析请假类型、起止时间、事由）、查询本人工资条、查询个人档案。

- **HR\-F\-42** 执行链路：意图识别 → 绑定当前登录员工身份鉴权 → 调用对应业务 API → 业务规则校验 → 返回结果；涉及创建或变更的高风险动作（如提交请假）必须先经员工二次确认。

- **HR\-F\-43** 权限边界：Agent 仅能访问当前登录员工本人的数据，继承系统行级权限；所有 Agent 操作写入审计日志；禁止代做审批、禁止修改薪酬数据。

- **HR\-F\-44** 技术实现：基于 LLM \+ Function Call（工具调用）编排，工具即现有业务 API（考勤查询、请假申请、工资条查询等）；无法确认的请求转人工或给出操作指引。

- **HR\-F\-45** 政策问答：导入公司制度文档（考勤、请假、福利、报销等）构建向量知识库（RAG），员工自然语言提问返回答案并附制度出处；查不到依据时明确提示未找到并转人工。

- **HR\-F\-46** 政策问答与员工自助 Agent 联动：制度检索作为 Agent 的子工具，回答政策类问题时优先走知识库检索。

# 核心业务流程

系统共五条核心流程，其中请假审批为最复杂的主链路，用泳道图表达角色交接；其余流程以步骤说明。

## 请假审批流程

员工提交后由系统校验，再路由部门主管审批，结果实时联动考勤与消息，全程状态可追溯。

## 考勤打卡流程

1. 员工在员工自助端点击上班打卡，系统记录打卡时间。

2. 下班再次打卡，生成当日考勤记录，并按规则判定状态（正常/迟到/早退/缺卡）。

3. 月末系统按员工汇总月度考勤，生成汇总数据供薪酬计算使用。

## 员工入职流程

1. HR 确认部门与岗位已存在（不存在则先创建）。

2. HR 在员工管理创建员工档案，系统自动生成工号。

3. HR 为该员工创建登录账号（绑定档案，设置初始密码）。

4. 员工首次登录修改密码，即可打卡、请假、查看工资条。

## 月度发薪流程

1. HR 选择发放月份，系统汇总当月考勤（出勤、请假、迟到等）。

2. 系统按薪酬档案与计算规则试算，生成草稿工资条。

3. HR 核对无误后确认发布，系统生成正式工资条并通知员工。

# 数据模型

核心实体关系如下，共 10 张业务表：user、department、position、employee、attendance\_rule、attendance\_record、leave\_type、leave\_request、leave\_approval、salary\_config、salary\_record（考勤规则表 attendance\_rule 单表存配置，不参与关系图）。

## 核心表字段清单

|表名|用途|关键字段|
|---|---|---|
|**user**|登录账号|- id、username、password\_hash<br>- role（ADMIN/MANAGER/EMPLOYEE）<br>- employee\_id（外键）、status、created\_at|
|**department**|部门（树形）|- id、name、parent\_id<br>- leader\_id（主管）、status|
|**position**|岗位字典|- id、name、code、status|
|**employee**|员工档案|- id、employee\_no、name、gender、phone、email<br>- id\_card（AES 加密）<br>- department\_id、position\_id（外键）<br>- hire\_date、status（在职/离职）<br>- emergency\_contact、emergency\_phone|
|**attendance\_rule**|考勤规则|- id、work\_start\_time、work\_end\_time<br>- late\_threshold、early\_leave\_threshold<br>- work\_days、single\_deduct（迟到单次扣款）|
|**attendance\_record**|考勤记录|- id、employee\_id、work\_date<br>- check\_in\_time、check\_out\_time<br>- status（正常/迟到/早退/缺卡/请假）<br>- adjust\_note（HR 调整说明）|
|**leave\_type**|请假类型|- id、name、code<br>- days\_per\_year（年假额度）、status|
|**leave\_request**|请假单|- id、request\_no、employee\_id<br>- leave\_type\_id、start\_date、end\_date<br>- start\_period、end\_period、days、reason<br>- status（草稿/待审批/已通过/已驳回/已撤销）|
|**leave\_approval**|审批记录|- id、leave\_request\_id、approver\_id<br>- action（通过/驳回）、comment、created\_at|
|**salary\_config**|薪酬档案|- id、employee\_id（1:1）<br>- base\_salary、allowance<br>- social\_security、housing\_fund<br>- effective\_date|
|**salary\_record**|工资条|- id、employee\_id、month<br>- base\_salary、allowance、attendance\_deduct<br>- social\_security、housing\_fund、tax<br>- net\_salary、status（草稿/已发布）|

# 非功能需求

## 安全

- 密码 BCrypt 加密存储，禁止明文；登录失败限流（同账号 5 次/小时锁定）。

- 全部业务接口做 RBAC 越权校验，员工不可访问他人数据（行级权限）。

- 身份证等敏感字段 AES 加密存储、列表脱敏；操作日志记录关键变更。

- 基础安全防护：SQL 注入、XSS、CSRF 防护，日志脱敏。

## 性能与可用性

- 常规接口 P95 响应小于 1 秒，页面首屏小于 2 秒，支撑 100 人规模日常使用。

- 单机部署（Docker \+ Nginx \+ 应用 \+ PostgreSQL \+ Redis），系统可用率目标 99%。

- PostgreSQL 每日自动备份，保留 30 天；应用日志留存 30 天。

## 兼容性与数据一致性

- 支持 Chrome / Edge 最新版本，移动端 H5 自适应。

- 请假审批通过后联动考勤、消息通知使用数据库事务，保证一致性。

- 金额字段使用 decimal，禁止浮点计算；时间统一存储 UTC、展示按本地时区。
